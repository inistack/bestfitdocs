This reference documents every endpoint of the BestFit Job Board API. Use it to
look up request fields, responses, and error codes. If you are new to the API,
start with the [quickstart](/quickstart) instead.

## Base URL

The Docker Compose setup serves the API at:

```text
http://localhost:5000
```

If you deploy the API elsewhere, replace this address in every request. The
paths have no version prefix, and this reference describes version 1.

## Request and response format

- Send `Content-Type: application/json` with every request that has a body.
- All responses are JSON, except `DELETE /jobs/{job_id}`, which returns `204`
  with no body.
- IDs are integers.
- Timestamps are ISO 8601 strings with no timezone offset, for example
  `2026-10-27T11:36:08.512345`. In the Docker Compose setup, treat them as UTC.

## Endpoints at a glance

| Group | Endpoints | Who can call them |
|---|---|---|
| Authentication | `POST /auth/register`, `POST /auth/login` | Anyone |
| Jobs (read) | `GET /jobs`, `GET /jobs/{job_id}` | Anyone |
| Jobs (write) | `POST /jobs`, `PUT /jobs/{job_id}`, `DELETE /jobs/{job_id}` | Employers |
| Applications | `GET /applications`, `POST /applications`, `GET /applications/{application_id}`, `GET /applications/{application_id}/status` | Candidates |
| Health | `GET /` | Anyone |

Protected endpoints need an access token. See [Authentication](/api/authentication)
for how to get one and send it.

## Try your first request

<Steps>
  <Step title="Check the API is running">
    ```bash
    curl http://localhost:5000/
    ```

    ```json
    {"message":"Welcome to the Job Board API!"}
    ```
  </Step>
  <Step title="List jobs">
    Listing jobs needs no token:

    ```bash
    curl "http://localhost:5000/jobs?location=remote&page_size=5"
    ```

    The response is an array of jobs. It is empty until an employer posts one.
  </Step>
  <Step title="Create an account">
    Register to get a token, then follow the [quickstart](/quickstart) to post a
    job and apply for it.
  </Step>
</Steps>

<Note>
  The API does not send CORS headers, so a browser cannot call it from another
  website. If an endpoint page's **Send** button fails with a network error, run
  the same request with `curl`, or use the Swagger UI the API serves at
  `http://localhost:5000/docs`.
</Note>

## Errors

Most errors use this shape:

```json
{
  "code": 404,
  "message": "Job with ID 42 not found",
  "status": "Not Found"
}
```

`code` is the HTTP status, `status` is its name, and `message` explains the
problem. Some errors, such as `429`, have no `message`.

Requests that fail validation return `422` and group the problems by location
and field:

```json
{
  "code": 422,
  "errors": {
    "json": {
      "password": ["Shorter than minimum length 8."]
    }
  },
  "status": "Unprocessable Entity"
}
```

Errors about the access token use a different shape. See
[Authentication](/api/authentication#fix-authentication-errors).

| Status | Meaning |
|---|---|
| `200`, `201`, `204` | The request succeeded. |
| `401` | The access token is missing or expired, or the login credentials are wrong. |
| `403` | The token is valid, but the account's role or ownership does not allow this action. |
| `404` | The job or application does not exist. |
| `409` | An account with that email already exists. |
| `422` | The request failed validation, or the token is malformed. |
| `429` | You exceeded a rate limit. |

## Pagination

`GET /jobs` is paginated. Control it with these query parameters:

| Parameter | Default | Limit | Description |
|---|---|---|---|
| `page` | `1` | 1 or more | The page to return. |
| `page_size` | `10` | 1 to 100 | The number of jobs per page. |

The `X-Pagination` response header describes the whole result set:

```text
X-Pagination: {"total": 23, "total_pages": 3, "first_page": 1, "last_page": 3, "page": 1, "next_page": 2}
```

`previous_page` and `next_page` appear only when those pages exist. A request
for a page past the end returns an empty array.

## Rate limits

`POST /applications` allows 10 requests per hour for each candidate. The 11th
request in that window returns `429 Too Many Requests`. The API does not send
rate limit headers, so wait up to an hour or use a different candidate account.
No other endpoint is rate limited.
