title: Authentication
description: Get an access token, send it with each request, and fix the authentication errors you are most likely to see.
---

The API uses JSON Web Tokens (JWTs) as bearer tokens. You get a token when you
register or log in, then send it in the `Authorization` header of every request
to a protected endpoint. Endpoints that list or read jobs, and the register and
login endpoints, need no token.

## Get an access token

Registering returns tokens immediately, so you do not need to log in afterward.

<Tabs>
  <Tab title="Register">
    ```bash
    curl -X POST http://localhost:5000/auth/register \
      -H "Content-Type: application/json" \
      -d '{
        "email": "jeni.okafor@example.com",
        "name": "Jeni Okafor",
        "password": "correct-horse-battery",
        "role": "candidate"
      }'
    ```

    The `role` is either `employer` or `candidate`, and the password needs at
    least 8 characters. The response has status `201`.
  </Tab>
  <Tab title="Log in">
    ```bash
    curl -X POST http://localhost:5000/auth/login \
      -H "Content-Type: application/json" \
      -d '{
        "email": "jeni.okafor@example.com",
        "password": "correct-horse-battery"
      }'
    ```

    The response has status `200`.
  </Tab>
</Tabs>

Both endpoints return the same body. The values below are shortened examples;
real tokens are much longer.

```json
{
  "access_token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9.<payload>.<signature>",
  "refresh_token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9.<payload>.<signature>"
}
```

## Send the token

Put the `access_token` in the `Authorization` header, after the word `Bearer`:

```bash
curl http://localhost:5000/applications \
  -H "Authorization: Bearer <access_token>"
```

Replace `<access_token>` with the token from the previous step. Send the
`access_token` only. The `refresh_token` is rejected on protected endpoints.

<Tip>
  In Swagger UI at `http://localhost:5000/docs`, select **Authorize** and paste
  the access token without the `Bearer` prefix. Swagger UI adds it for you.
</Tip>

## Know how long tokens last

| Token | Default lifetime | Use |
|---|---|---|
| `access_token` | 15 minutes | Authenticate requests. |
| `refresh_token` | 30 days | None yet. No endpoint accepts it. |

When an access token expires, log in again at `POST /auth/login` to get a new
one. Your client should do this when it receives a `401` with the message
`Token has expired`.

## Understand roles

Every account has one role, chosen at registration and stored inside the token.
Each protected endpoint requires a specific role.

| Role | Can do | Cannot do |
|---|---|---|
| `employer` | Create, update, and delete jobs. | Apply for jobs or read applications. |
| `candidate` | Apply for jobs, list their own applications, and check their status. | Create, update, or delete jobs. |

A candidate can read only their own applications. Requesting another
candidate's application returns `403`.

## Fix authentication errors

Errors about the token itself use a short `msg` shape. Errors about roles,
ownership, and credentials use the [standard error shape](/api/introduction#errors).

| Status | Response | Cause | Fix |
|---|---|---|---|
| `401` | `{"msg": "Missing Authorization Header"}` | The request has no token. | Add the `Authorization: Bearer <access_token>` header. |
| `401` | `{"msg": "Token has expired"}` | The access token is older than its lifetime. | Log in again at `POST /auth/login`. |
| `422` | `{"msg": "Not enough segments"}` or `{"msg": "Signature verification failed"}` | The token is malformed, was altered, or was signed with a different secret key. | Send the full `access_token` exactly as returned, from the same running stack. |
| `422` | `{"msg": "Only access tokens are allowed"}` | You sent the `refresh_token`. | Send the `access_token` instead. |
| `401` | `"message": "Invalid email or password"` | The login email or password is wrong. | Check the credentials. |
| `403` | `"message": "Employer role required"` or `"Candidate role required"` | The token's role does not match the endpoint. | Use a token from an account with the required role. |
| `403` | `"message": "Not your application"` | The application belongs to another candidate. | Use the token of the candidate who applied. |
| `409` | `"message": "User with this email already exists"` | The email is already registered. | Log in instead. |

<Warning>
  Tokens are signed with the `JWT_SECRET_KEY` in your `.env` file. If you change
  it, every existing token stops working and users must log in again. Keep the
  value private and never commit your `.env` file.
</Warning>
